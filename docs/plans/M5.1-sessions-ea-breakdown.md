# M5.1 — Session + EA/Discretionary breakdowns

**Goal.** Add two behaviour-breakdown views to `journal report`: performance by
**trading session** (UTC hour buckets) and by **trade source** (EA vs
discretionary). Both reuse M5's `_MIN_N=20` gating (docs §9) — most buckets will
read "insufficient data" for a long time, by design. No schema change, no
migration, `domain/reconstruct.py` untouched.

**Decisions locked (2026-07-18).**
- Session model = **fixed UTC trading-session windows** (not hour/day-of-week).
- Output surface = **extend `journal report`** (new sections; extend
  `ReportResult` / `build_report`), not new subcommands.

### Data already on `trades` (no schema change needed)
`src/journal/store/schema.sql`, `CREATE TABLE trades`:

  broker server clock **is UTC** — `server_utc_offset_s = 0`, confirmed

  read directly, **no offset conversion** at analytics time.
- `magic INTEGER` (nullable) — populated by reconstruct from the IN deal's
  magic (`domain/reconstruct.py:379` → stored at `:561`). **Verified present.**
- `status`, `net_profit`, `r_multiple`, `symbol_base` — as used by M5's report.

### EA vs discretionary is a measured clean split
`docs/mt5-deal-model.md:679-695` (§7): over 68 opening orders,
`magic != 0` ⟺ `reason == EXPERT(3)` ⟺ `sl != 0` — **the same 6 trades**.
Discretionary (`magic == 0`) = 62. **Classify on `magic` alone**: truthy → EA,
`0`/`NULL` → discretionary. (Rule 4: `NULL` = unknown; an unknown magic must
**not** silently become EA — fold it into discretionary and document it.)
EA population is 6, so every EA averaged stat stays gated by §9 indefinitely —
build the split anyway; the pipeline is the point (§9's own instruction, already
proven by M5's R-multiple sections).

### Session hours vary per symbol — a bucketing hazard, not a footnote
`docs/mt5-deal-model.md:654-665` (§7): BTCUSDc 24/7 · EURUSDc ≈24h×5d · XAUUSDc
≈23h×5d (gold has a ~1h daily break). **Consequence for M5.1:** a low count in a
session bucket may mean "symbol wasn't open then", not "trader avoids it" — the
report must not imply otherwise. We bucket *when trades opened*; we never divide
by a "hours available" denominator (that would need per-symbol calendars we
haven't built). Keep buckets as raw counts + gated stats only.

### Canonical epoch-ms → UTC idiom (COPY THIS; do not invent)
`ingest/candles.py:49`, `render/chart.py:177`, `cli.py:412,583` all use:
```python
datetime.fromtimestamp(msc / 1000, tz=timezone.utc)
```
**Anti-pattern guard:** do **not** use `datetime.utcfromtimestamp(...)`
(deprecated, returns naive — violates rule 3's "never naive"). Match the repo.

**Write the test first** (rule 7): `tests/test_sessions.py`.

New file `src/journal/analytics/sessions.py`. One module constant + one pure
function. Boundaries are **half-open `[start, end)`**, UTC hour of
`open_time_msc`. Five buckets, fixed chronological order:

| label      | UTC window     |
|------------|----------------|
| `Asian`    | 00:00–07:00    |
| `London`   | 07:00–12:00    |
| `LDN/NY`   | 12:00–16:00    |
| `New York` | 16:00–21:00    |
| `Late`     | 21:00–24:00    |

```python
SESSION_ORDER: tuple[str, ...] = ("Asian", "London", "LDN/NY", "New York", "Late")

def session_of(open_time_msc: int) -> str:
    """Trading session an epoch-ms (UTC) open time falls in. Server clock is
    UTC (server_utc_offset_s=0, docs §7) so the hour is read with no offset."""
    hour = datetime.fromtimestamp(open_time_msc / 1000, tz=timezone.utc).hour
    ...  # half-open [start,end) ladder over the table above
```

## Phase 2 — extend `build_report` with bucket aggregation (TDD)

**Extend `tests/test_report.py` first** (rule 7).

In `analytics/report.py`:

1. Add a small frozen result type for one bucket:
```python
@dataclass(frozen=True)
class BucketStat:
    label: str
    n: int                    # closed trades in bucket — RAW COUNT, always shown
    win_rate: float | None    # None if n < _MIN_N (gated) or n == 0
    expectancy: float | None  # mean net_profit; None if n < _MIN_N or n == 0
    n_with_r: int             # raw diagnostic, always shown
    avg_r: float | None       # None unless n_with_r >= _MIN_N
```
   Gating rule (mirror M5 exactly): **every *averaged* field is pre-gated to
   `None` in `build_report`; raw counts (`n`, `n_with_r`) are never gated.**
   win_rate and expectancy are averages/ratios → gated by the bucket's own `n`.

2. Add to `ReportResult`:
```python
    by_session: tuple[BucketStat, ...]   # SESSION_ORDER, all 5 always present
    by_source: tuple[BucketStat, ...]    # ("EA", "Discretionary"), both present
```

3. `build_report`: extend the closed-trades SELECT to also fetch
   `open_time_msc, magic`. Add a private helper that takes a list of rows + a
   label and returns a `BucketStat` (same math as the top-level report:
   tolerance-based win via `_TOL`, expectancy = mean net_profit, avg_r over
   non-NULL r gated at `_MIN_N`). Reuse it for both breakdowns:
   - session: group rows by `session_of(row["open_time_msc"])`; **emit all 5
     buckets in `SESSION_ORDER`** even when empty (n=0 → all-None, stable table).
   - source: `"EA"` when `row["magic"]` is truthy else `"Discretionary"`; emit
     both buckets always.

**Verification checklist (Phase 2):**
- [ ] Session assignment: seed trades at known `open_time_msc` in each window →

- [ ] All existing `test_report.py` cases still pass unchanged.
